# 两周 Agent 基础学习计划

## 目标与边界

- 周期：14 个学习日，每天 4 小时，共 56 小时。若从 2026-10-15 开始，对应 10-15 至 10-28；也可以顺延。
- 起点：已理解基本 Tool Calling 和 Agent Loop，尚未开始仓库实验。
- 目标：读懂一条完整轨迹，理解上下文对行为的影响，并独立实现一个最小 Agent。
- 本轮聚焦第一章和第二章的 API 消息、工具调用部分。不追求学完两章，不做训练、图像生成、复杂框架与完整基准复现。
- 先离线理解，再按需接真实模型。离线脚本的预设行为不代表模型具备自主决策能力。
- 这是校准计划；第 7 天和第 14 天根据实际表现调整后续节奏。

## 每天怎样用这 4 小时

一般学习日：15 分钟闭卷回忆，45 分钟定向阅读，120 分钟追踪代码或动手，45 分钟独立练习，15 分钟记录。
第 7、14 天把阅读和练习时间改为验收与补漏。4 小时指有效学习时间，休息另计；可拆成上午、下午各 2 小时。

每个实验都回答：解决什么问题？Context 在哪里？LLM 调用在哪里？Tools 在哪里？Controller/Loop 在哪里？数据怎样流动？什么条件使它停止？

| 3 | 定向阅读 `book/chapter2.md` 的四种消息角色、带工具调用的多轮交互；手写一条含工具调用的消息序列，对照仓库实现。 | 解释 assistant 工具调用、tool 结果及调用标识怎样对应；预测漏回填结果会怎样。 |

| 6 | 条件允许时，用同一模型、任务和参数做完整上下文与移除工具结果的最小对照；否则分析已有轨迹并完成离线消息变换。 | 写下预测、观察、解释和局限；不能把离线结果或一次运行当作模型能力结论。 |

## 第二周：逐步独立实现最小 Agent

默认作品是“本地学习笔记助手”：读取指定练习目录内的 Markdown 笔记，回答问题，并给出所用文件名。它通过普通文件工具获取材料，不使用向量库或 RAG 框架。

| 天 | 阅读与动手任务 | 当天验收与产物 |
| --- | --- | --- |
| 8 | 写清输入、输出和边界；准备 3～5 份不含隐私的短笔记；定义 `list_notes`、`read_note` 两个工具的参数与返回值。 | 写出 5 个验收问题，至少包含资料不足和文件不存在；画出作品的数据流。 |
| 9 | 自己实现本地工具，限定读取范围，只允许读取准备好的笔记。先直接调用函数，不接模型。 | 正常读取、文件不存在、越界路径三种情况有明确结果；不使用任意 shell 执行或 `eval`。 |
| 10 | 在新文件中从空白实现消息列表、动作分发、结果回填和循环上限；先用脚本响应检查控制流。 | 能完整走通“列目录→读笔记→回答”；能解释这时为什么还不能称为真实模型驱动的 Agent。 |
| 11 | 条件允许时接入一个真实模型，先完成单次调用，再接回工具循环。SDK 字段和鉴权可以查文档，核心循环先自己写。 | 真实轨迹中模型自行选择工具，收到工具结果后回答；若未接 API，明确记录联网验收未完成。 |
| 12 | 补工具参数错误、未知工具、工具失败、循环上限的处理；若已联网，再检查超时与请求失败。先预测，再手动制造故障。 | 每类故障都能定位并明确停止或返回错误；不做无限重试，不把工具错误伪装成成功。 |
| 13 | 用第 8 天的 5 个问题验收，记录是否调用正确工具、答案是否有依据、能否正确表示资料不足；只修最影响结果的问题。 | 形成一张结果表；分清程序跑完、答案正确、答案有依据三件事。 |
| 14 | 不看原实现，用 60～90 分钟重写核心循环；再讲解自己的作品，复盘两周耗时与求助点。 | 保存重写版本、简短使用说明和复盘；更新学习进度，按证据安排下一阶段。 |

## 环境、费用与卡点处理

- 环境准备累计超过 60 分钟仍未解决，当天先读代码与轨迹，单独记录报错；不要让安装占满学习日。
- 真实 API 调用前确认提供商、可用凭据和可接受预算；只做少量短任务，不运行完整批量评测。密钥不进入笔记、日志或提交。
- 接口不可用时继续完成离线控制流；最终标记真实模型调用为待验收，不能算作已经跑通。
- 独立练习先自己尝试 20～30 分钟，再请求提示。优先要定位线索，不直接索取完整代码。
- 如果第 7 天仍无法解释结果回填与终止条件，第二周优先补基础，缩减作品功能，不额外加课时。
- 暂时不强行学习 async/await；只有所选调用路径确实需要时再补。查 SDK 用法正常，不能靠复制整个 Agent 来通过验收。

## 第 14 天的判断标准

分别记录“独立完成 / 需要提示 / 尚未完成”，不只打总分：

1. 能从代码定位 Context、LLM、Tools、Controller 与终止条件。
2. 能追踪一条工具调用如何进入上下文，并解释调用与结果的对应。
3. 能独立新增一个简单工具，处理一次失败并限制循环。
4. 能从空白重写核心循环，允许查 SDK 文档。
5. 能用轨迹判断答案是否使用了工具提供的依据。
6. 若 API 条件具备，能完成一次真实模型驱动的工具闭环；否则单独列为待验收。

据此决定继续上下文工程，还是再安排一周巩固。两周的成果是可展示的代码与理解证据，不以读完多少页作为完成标准。
